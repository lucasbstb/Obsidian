## Merge da `lucasdev` na `main`, e as branches no remoto

**O quê:** os 7 commits da `lucasdev` foram para a `main`, e as duas branches
passaram a existir no GitHub.

**Por quê:** **a produção do front puxa `main`.** Isso só ficou evidente ao
preparar o deploy — a `main` estava em `22b9203`, já publicada, e todo o
trabalho dos últimos dias vivia na `lucasdev` **sem upstream**. Sem o merge, o
`git pull origin main` no servidor não traria nada.

### Um susto que não era susto

O `git merge-base --is-ancestor` acusou que as branches **divergiram**. Parecia
merge complicado. Não era:

```
na main e nao na lucasdev:   22b9203  (commit de MERGE, sem conteudo proprio)
na lucasdev e nao na main:   7 commits de trabalho
base comum:                  0fb3fff
```

O `git diff --stat 0fb3fff main` voltou **vazio** — a `main` não tinha nenhum
conteúdo além da base comum. A divergência era só topológica, causada por um
commit de merge anterior. O merge saiu limpo e a `main` ficou com árvore
idêntica à `lucasdev`.

**Vale como método:** divergência de *commits* não é divergência de *conteúdo*.
Antes de temer um merge, comparar as árvores.

**Commit:** `4ce1865` (merge na `main`)

## Deploy em produção

8 commits: o redesign da tela de API Keys, o diálogo de revogar, o catálogo de
scopes por rota e os três espelhos de escopo anteriores. Detalhes do que cada um
faz em [[2026-08-13]].

### A limpeza do `.next` foi obrigatória desta vez

Não por precaução: a tela de API Keys é **a primeira de conteúdo** a usar os
tokens do `@theme` (`bg-surface`, `text-ink`, `text-gold`), e o sintoma
documentado da armadilha é exatamente esse — valor arbitrário funciona, token do
tema não.

```bash
docker exec atjewel_app sh -c 'rm -rf /app/.next/* /app/.next/.[!.]* 2>/dev/null; true'
docker restart atjewel_app
```

Funcionou de primeira: a tela subiu com o layout novo. Procedimento em
[[Deploy do front em produção]].
