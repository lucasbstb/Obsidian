**Primeiro engano: a falha acontece DEPOIS do envio.** O `extrairEGravar` roda

**Segundo engano: a linha mudava mesmo assim.** O ATwpp chama `/leads` **duas
vezes por mensagem** — uma antes de responder, sem dado nenhum, só para saber
com quem está falando; outra depois, com o que a extração achou. A primeira
mexe no `atualizado_em` a cada turno. O lead parecia vivo.

> ficava vazia.

## 2. A causa

```
1. chama o LLM para responder
2. registra o turno do USUÁRIO
3. envia pelo WhatsApp
4. registra o turno da ASSISTENTE   ← o histórico termina aqui
5. extrairEGravar(msg, historico.turnos)
```

A extração recebia um array terminando em `assistant`. Para a API isso é um
**prefill** — e prefill não é aceito junto de structured outputs:

```
400 invalid_request_error
"included an `assistant` message in the final position, which would
 pre-fill the `assistant` response. When using output format,
 pre-filling the `assistant` response is not supported."
```

Toda extração estourava, caía no `catch`, devolvia `null`. O segundo POST nunca
saía. **Desde o deploy de 28/08.**

---

## 3. O método — e o falso negativo que quase enterrou o diagnóstico

Quatro chamadas contra a API real, variando **uma coisa por vez**:

| array de mensagens | schema | resultado |
|---|---|---|
| termina em `assistant` | antigo | **400 prefill** |
| termina em `assistant` | `anyOf` | **400 prefill** |
| termina em `user` | antigo | extraiu tudo |
| termina em `user` | `anyOf` | extraiu tudo |

A primeira rodada deu **"funciona nos dois casos"** e quase me fez descartar a
hipótese certa — porque o array que eu montei para o teste terminava em `user`.
O teste é que estava errado, não o diagnóstico.

> **A lição, e ela é geral:** quando o teste diz que o bug não existe, conferir o
> teste antes de abandonar a hipótese. Um controle mal montado é indistinguível
> de uma teoria errada.

O schema com `type: ['string','null']`, que era o segundo suspeito, foi
**inocentado** — e a mudança que eu já tinha feito nele foi **revertida**. Deixar
no repo uma alteração cujo comentário afirma consertar algo que o teste desmente
é pior que não ter mexido.

## 4. O conserto

A conversa vai para a extração como **transcrição num único turno de usuário**,
delimitada em `<conversa>`. Os papéis viram rótulo dentro do texto.

Some o prefill, e some também a dependência da ordem dos turnos: extrair é ler
um texto, não continuar um diálogo.

### As duas linhas que teriam entregado isso em dez segundos

**O log passou a trazer status e mensagem da API.** `String(err)` sozinho não
distingue um 400 de schema de um 429 de limite — e as duas pedem coisas opostas.

**`stop_reason === 'max_tokens'` passou a avisar.** Teto estourado devolve JSON
pela metade e `parsed_output` vazio **sem erro nenhum** — sintoma idêntico ao de
"a conversa não tinha nada": lead em branco e log limpo.

  chegou
