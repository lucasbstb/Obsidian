## 1. O lock de quinze horas

```
 pid | state               | query                                    | xact_start
-----+---------------------+------------------------------------------+--------------------
 391 | idle in transaction | select (select count(*) from incident_tr  | 2026-09-01 16:28:20
 876 | active              | INSERT INTO incident_trafficincident (ne | 2026-09-01 20:20:27
```

A PID 391 é a sessão onde rodei `BEGIN; TRUNCATE ...` e a consulta de
conferência. **O `COMMIT` nunca foi digitado.** O `TRUNCATE` segurava lock
`ACCESS EXCLUSIVE` desde as 16:28.

Às 20:20 o script entrou na fila. E ficou.

> **Matar o processo Python não resolve.** O backend do Postgres continua
> esperando o lock — o cliente ter morrido só é percebido quando a query termina.
> Foi preciso `pg_terminate_backend` nos dois.

Ao matar a 391, o rollback devolveu os 31.069 sinistros. O banco voltou
exatamente ao estado da véspera, o que pelo menos deu uma prova de que a
transação estava mesmo intacta.

### A regra que fica

Comando único vai pela forma não interativa, que faz autocommit e fecha a sessão
sozinha:

```powershell
docker exec <container> psql -U admin -d <banco> -c "COMANDO"
```

E um `TRUNCATE` já é atômico por natureza — o `BEGIN` não protegia nada que ele
não protegesse sozinho. Só criou a chance de esquecer o `COMMIT`.

> Detalhe traiçoeiro: com `-c`, um `BEGIN` **sem** `COMMIT` na mesma string faz o
> psql dar rollback ao sair. O comando é desfeito e nada avisa.

O prompt do psql avisa o tempo todo, e eu não estava olhando:
`vidadev=#` normal, `vidadev=*#` transação aberta, `vidadev=!#` abortada.

## 3. O `NaN` que virava texto

```
event              | NaN
textual_reference  | NaN
```

Célula vazia na planilha vira `NaN` no pandas, e o script gravava **a string
literal "NaN"** no banco. Não é `NULL`: `WHERE campo IS NULL` deixa de achar, o
export imprime "NaN" e a tela mostra isso ao usuário.

Em 31 mil registros, viraria sujeira difícil de limpar.

A correção é uma linha — e curiosamente o `criacao_registros_cbrj.py` já a
tinha, enquanto o `migracao.py` não:

```python
df = df.where(pd.notna(df), None)
```

Vale para **todos** os blocos de uma vez. Testado: os dois campos agora vêm
vazios, e o `geom` continua preenchido.

> **duplicaria quase quatro anos**. Como estamos truncando antes, não é problema
> agora. Mas quando isso for para o ambiente de verdade, será preciso filtrar por
> `data_fato >= 01/05/2025`.

`desc_local_fato` sumiram. **A comparação completa ainda não foi feita** — é o

## 4b. O banco de dev está incompleto — 14 tabelas faltando

Ao subir o front, o mapa quebrou duas vezes seguidas. As duas causas eram dado ou
schema ausente, não código:

**Primeira:** `Invalid time value` em `dateUtils.ts`. A página do mapa procura
`management_dates` com `id = 1`, e a única linha da tabela tinha **`id = 2`** —
alguém apagou e reinseriu, e a sequência deu 2. O `find` devolvia `undefined`, e
`formatDate(startDate!)` estourava. Aquele `!` é uma asserção de não-nulo sobre
algo que pode perfeitamente ser nulo.

**Segunda:** `Cannot read properties of undefined (reading 'data')`. A tabela
`incident_annual_report` **não existe** no banco de dev.

Em vez de caçar uma por tela, comparei as entidades do código com o schema:

```
78 entidades no código  ·  68 tabelas no banco
```

| Faltando | Impacto |
|---|---|
| `incident_annual_report` | quebra `/sinistro/mapa` |
| `incident_similarincidents` | quebra `/sinistro/duplicidades` |
| `education_*` (12 tabelas) | módulo de Educação — menu comentado, ninguém chama |

O banco de dev foi restaurado de um dump incompleto, ou de uma versão anterior
do schema.

> **É o custo direto de não haver migrations no repositório.** Com elas, alinhar
> o schema seria um comando; sem elas, é engenharia reversa das entidades.

### O que foi feito no banco de dev

As duas tabelas de `incident_*` foram criadas vazias em 02/09/2026 — o endpoint
passa a devolver `{status: 200, data: []}` em vez de estourar:

```bash
docker exec vida-rio-dev psql -U admin -d vida -c "CREATE TABLE IF NOT EXISTS incident_annual_report (id SERIAL PRIMARY KEY, label VARCHAR NOT NULL, filename VARCHAR NOT NULL, filepath VARCHAR NOT NULL, uploaded_at TIMESTAMP NOT NULL DEFAULT now())"

docker exec vida-rio-dev psql -U admin -d vida -c "CREATE TABLE IF NOT EXISTS incident_similarincidents (id SERIAL PRIMARY KEY, traffic_incident_id INTEGER NOT NULL REFERENCES incident_trafficincident(id), traffic_incident_similar_id INTEGER NOT NULL REFERENCES incident_trafficincident(id))"
```

⚠️ **Esse DDL foi reconstruído a partir das entidades TypeORM, não do schema
real.** Pode divergir de produção em tipos, tamanhos, índices e regras de
`ON DELETE`. Substituir pelo `pg_dump -s` de um banco completo quando houver
acesso.

As 12 tabelas `education_*` continuam ausentes — o módulo está com o menu
comentado no front, então nada quebra por ora.

⚠️ **Não** usar `synchronize: true` para isso. Ele tentaria alinhar o schema
inteiro e pode alterar colunas numa base com 42 mil sinistros.

O DDL correto deve vir de um banco completo:
```powershell
docker exec db-vida pg_dump -U admin -d vida -s -t "education_*" -t incident_annual_report -t incident_similarincidents -f /tmp/faltantes.sql
```

### E um padrão no front que esconde erro

```tsx
let register: any = [];
try {
  const res = await callService({...});
  register = res.resData?.data;   // ← sobrescreve o [] com undefined
} finally {
  return register;
}
```

O fallback `[]` é destruído quando a chamada falha. A página então faz
`annualReports.data.map(...)` e quebra com uma mensagem que não diz nada sobre a
causa real. O erro verdadeiro (o status HTTP) só aparece no **terminal do
front**, porque `callService` roda como Server Action.

## 5. Coisas que descobrimos e valem lembrar

- **`BEGIN` sem `COMMIT` trava tudo em silêncio.** Para comando único, use
  `psql -c` e deixe o autocommit trabalhar
- **matar o cliente não solta o lock** — precisa de `pg_terminate_backend`
- o prompt do psql já dizia: **`=*#` é transação aberta**
- **`NaN` do pandas vira a string "NaN"** no banco se não passar por
  `df.where(pd.notna(df), None)`
- **`geom` vem pronto na planilha do ISP** — EWKB, sem geocodificação
- **o `.gitignore` pode engolir o `package.json`** — `*.json` é uma regra
  perigosa demais
- no CET, a porta **5432 é o `db-vida`** (homologação) e a **5433 é o
  `vidadev`**. O container sem "dev" no nome é o de produção-ish
